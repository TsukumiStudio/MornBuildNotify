MornBuildNotify

GitHub Actions の進捗と結果を、1つの Discord メッセージを書き換えながら通知する Action。

できること

START

ビルド開始でメッセージを1つ送る

UPDATE

各 step から morn-build-notify update で進捗へ書き換え

FINISH

結果・工程・ログ・リンクへ置き換え

  • チャンネルに流れるのは1ビルド1メッセージ。途中経過で埋まらない
  • 結果は成功・失敗・中止・スキップ。工程ごとの ✅ / ❌ / ⏭️ を段に分けて並べられる
  • 失敗時は、失敗した job のログから ::error の内容（無ければエラーらしい行）を抜き出して載せる
  • 失敗時はコミット作者を Discord でメンションする（GitHub ログイン名 → Discord ID の表）
  • 配布リンクなどの欄を自由に足せる。値が空なら出ない
  • 通知に失敗してもビルドは止めない。Webhook URL はログに出さない
  • 依存は python3 と gh だけ（GitHub-hosted runner には入っている）
❌ 公開失敗: owner/repo
@作者 ビルドが失敗しました。確認をお願いします。
コミット ／ 工程結果（✅ Checkout ❌ テスト ⏭️ 公開） ／ ログ ／ ビルドエラー詳細

導入（ウィザード）

対象リポジトリのルートで1行実行する。質問に答えると、設定ファイルと workflow を書き出し、Webhook を Secret へ登録する。

python3 <(curl -fsSL https://raw.githubusercontent.com/TsukumiStudio/MornBuildNotify/v1/init.py)

既存ファイルは上書きするか毎回聞く。書き出したものをコミットして push すれば通知が届く。

既存の workflow へ足す

permissions:
  contents: read
  actions: read            # 工程結果と失敗ログの取得に使う

jobs:
  notify-start:
    runs-on: ubuntu-latest
    outputs:
      message-id: ${{ steps.notify.outputs.message-id }}
    steps:
      - uses: actions/checkout@v4
      - id: notify
        uses: TsukumiStudio/MornBuildNotify@v1
        with:
          webhook: ${{ secrets.DISCORD_WEBHOOK }}
          mode: start

  build:
    needs: notify-start
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: TsukumiStudio/MornBuildNotify@v1     # setup
        with:
          webhook: ${{ secrets.DISCORD_WEBHOOK }}
          message-id: ${{ needs.notify-start.outputs.message-id }}
      - run: |
          morn-build-notify update "テスト中"
          ./test.sh

  notify:
    needs: [notify-start, build]
    if: ${{ always() }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: TsukumiStudio/MornBuildNotify@v1
        with:
          webhook: ${{ secrets.DISCORD_WEBHOOK }}
          mode: finish
          message-id: ${{ needs.notify-start.outputs.message-id }}
          needs: ${{ toJSON(needs) }}

入力

webhookDiscord Webhook URL。空なら何もしない
modesetup（既定）／ start ／ finish
message-idstart の出力。渡すと同じメッセージを更新する
statusfinish の結果。空なら needs から決める（中止 > 失敗 > 全成功 > スキップ）
needs${{ toJSON(needs) }}
fields足す欄。1行1項目の 名前: 値。\n で改行、値が空の行は出ない
sha通知に載せるコミット（既定 github.sha）
config設定ファイル（既定 .github/morn-build-notify.json）

条件付きの欄

式で値を空にすると、その欄は出ない。成果物があるときだけリンクを載せられる。

fields: |
  遊ぶ: ${{ needs.build.outputs.url && format('[このビルドを遊ぶ]({0})', needs.build.outputs.url) || '' }}

設定ファイル

.github/morn-build-notify.json。すべて省略できる。

{
  "name": "MyGame",
  "username": "ビルド通知bot",
  "titles": {"success": "✅ 公開完了", "failure": "❌ 公開失敗"},
  "results": [
    {"name": "準備", "items": [
      {"label": "Checkout", "job": "build", "step": "Checkout"},
      {"label": "公開", "job": "publish"}
    ]}
  ],
  "errors": true,
  "mentions": {"your-github-login": "123456789012345678", "*": "123456789012345678"}
}
name進捗メッセージの見出し（既定はリポジトリ名）
username送信者名
titles結果ごとの見出し
results工程結果の段。job は job の表示名、step は step 名（省略で job の結果）。省略時は完了した job を並べる
errors失敗時にログ抜粋を載せるか（既定 true）
mentions失敗時に呼ぶ人。* は未登録時の宛先。無ければ誰も呼ばない
mention-messageメンションに続く文
